## 1. 数据集与决策者

**数据集：** [Hotel Booking Demand](https://www.kaggle.com/datasets/jessemostipak/hotel-booking-demand)
**文件：** `hotel_bookings.csv`（单文件，约 1 MB，119,390 行，32 列）

**数据来源与背景：**
数据来自 Nuno Antonio、Ana Almeida、Luis Nunes 发表于 *Data in Brief*（Volume 22, 2019）
的论文 *Hotel Booking Demand Datasets*，由 Thomas Mock 与 Antoine Bichat 为 #TidyTuesday
清洗整理。涵盖一家 **城市酒店（City Hotel）** 与一家 **度假酒店（Resort Hotel）** 的预订记录。

- **一行代表：** 一笔酒店预订
- **时间范围：** 2015 年 7 月 – 2017 年 8 月
- **数据性质：** 真实商业数据（已移除个人身份信息），非合成数据

**决策者（一个具体角色，不是"所有人"）：**
**酒店收益经理（Revenue Manager）** —— 负责定价、房量配额与超售控制。

## 2. 为什么需要这个仪表盘（Justification）

**谁看、多久看一次？**
酒店收益经理，**每周一**在做下阶段房量与配额计划时查看。

**支持什么决策？**
> 如果收益经理看到**某个市场细分（渠道）的取消率显著高于整体平均**，
> 他就会**下调该渠道的房量配额，或对该渠道启用更严格的押金政策**，
> 以减少空房损失。

**今天没有它，他们会怎么做？代价是什么？**
目前靠月末从 PMS 导出 Excel、手工计算取消率，**滞后 2–4 周**。
旺季空房无法及时回补，直接造成营收损失；且无法按渠道快速定位问题来源。

**为什么是仪表盘，而不是周报/邮件/告警？**
取消率**每天都在变**，且需要**按渠道反复、多维地看**同一个问题。
一次性分析回答不了"这周哪个渠道出问题了"。因此它是一个**持续复用**的工具，
符合仪表盘的使用场景。而针对单一渠道的突发异常，则用**告警**（见第 4 节）来补充。

## 3. 展示什么、砍掉什么

### 头条 KPI（5 秒内看到，`st.metric` 三列并排）
1. **总取消率**
2. **平均日房价（ADR）**
3. **总预订量**

### 支撑图表（解释 KPI 为什么动）
1. **取消率月度趋势** —— 反映旺季/淡季的取消行为差异
2. **各市场细分取消率对比** —— 定位"问题渠道"

### 过滤器（只放决策者真正用的）
- **酒店类型**（City / Resort）：两类酒店经营逻辑完全不同，必须分开看
- **市场细分**（多选）：收益经理能直接动手的维度就是渠道配额

### 刻意不展示的两样东西
1. **按国家（country）的取消率分析**
   理由：国家维度过于分散（上百个国家），且**收益经理无法按国家调整配额**，
   看到结果也不会改变任何行动。渠道才是可操作的维度。
2. **`assigned_room_type` 与 `reserved_room_type` 是否一致的深挖**
   理由：EDA 中确实有趣（可能反映超售/升级），但**收益经理无法据此采取具体行动**，
   属于"看着有意思、但不改变决策"的典型，故砍掉。

> 检验标准：如果某个元素消失，决策者会察觉吗？不会，就砍掉。

### 页面顺序（从上到下 = 从重要到次要）
1. **顶部：** 三个头条 KPI —— 回答"现在有没有问题？"
2. **中部：** 两张解释性图表 —— 回答"为什么这个数字在动？"
3. **底部：** 原始明细表（可折叠）—— 给想深挖的人

## 4. 数据陷阱与刷新频率

### 可能误导观众的地方（及处理方式）
| 问题 | 处理方式 |
|---|---|
| `children`、`company`、`agent` 列存在大量缺失值 | 在页脚注明；分析时不依赖这些列 |
| `adr`（平均日房价）存在负值与极端异常值（如 5400） | 计算前剔除 `adr < 0` 或 `adr ≥ 1000` 的记录 |
| 数据截至 2017 年，不代表当前市场 | 页脚明确标注"Kaggle 快照，2015–2017" |
| 部分月份时间戳可能缺失 | 时间序列图自动跳过空值，不做插值 |

### 刷新频率决策（生产环境设想）
- **数据刷新：** **每日刷新**。取消行为每天都在发生，月度汇总太滞后。
- **审阅频率：** **每周一**，与收益经理做配额计划的节奏一致。
  刷新频率（每日）与审阅频率（每周）**不必相同** —— 数据可以天天更新，
  但不需要天天看。
- **告警指标：** 选定"某渠道的周取消率"。当它 **超过历史均值 15%** 时，
  触发邮件告警，让收益经理**当天**介入，而不必等到周一。
- **实时刷新的取舍：** 不采用实时刷新 —— 决策按周做，实时刷新只会增加
  从多个 PMS 系统拉数的成本，却不会改变任何决策。
- **陈旧数据的代价：** 若看板落后一周，旺季可能错失回补空房的最佳时机，
  按渠道定位问题也会滞后，直接体现为可量化的营收损失。
